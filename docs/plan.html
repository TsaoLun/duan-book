DUAN

里程碑

这份文档回答一个问题：接下来该做什么，怎么知道做完了。

每个阶段写四件事：做出什么、怎么判定做完、依赖哪些阶段、要先学哪些单元。终点的模型长什么样见 design.md，怎么学见 learn/README.md。

完成标准尽量写成测试。先用 #[ignore = "PN"] 标记，实现之后去掉 ignore，测试通过就算完成这一项。所以随时可以问「还差多少」：

cargo test --workspace -- --ignored     # 列出的就是还没达成的标准

  • 主线：P1 到 P4。 做完这四个阶段就到了终点。P1、P2、P3 之间没有依赖，可以按任意顺序做。
  • 补全：P6、P8。 让模型可以发布：校准可信，延迟可测。
  • 可选：P5、P7、P9。 有需要再做，不影响终点。

终点

满足 design.md 第 1 节的验收标准：

  • 在中文评测集上，NLL 和 ECE 优于用同一批数据、同样损失微调的 laya-multilingual；
  • 至少 3 个随机种子；
  • 选项翻转率接近 0。

做不到时，在报告里如实写出差距，并重新评估选 Qwen3 的理由。这同样算完成。

主线

P0 读懂设计

  • 产出： 学习者自己画的数据流图和可见矩阵，写在 notes/ 里。
  • 完成标准： 不看资料，讲得清 design.md 第 3 节的布局为什么是这样：标记为什么在选项后面，位置为什么要重计，state 为什么放最前面。还要能说出 Laya 的三个缺陷各由哪个设计来解决，以及第 4.1 节里那四条被排除的路线各付什么代价、为什么放弃。
  • 依赖： 无。
  • 单元： U0 到 U5。

P1 指标与温度

  • 产出： crates/duan-calib 中的 nll、brier、ece，以及 temperature::fit。
  • 完成标准： cargo test -p duan-calib -- --include-ignored 全部通过。其中：
    • metrics::tests 的三个测试：和手算结果一致；
    • tests/kime_parity.rs：在随机数据上，和 kime-eval 的 ECE、Brier、NLL 相差都小于 1e-12；
    • temperature::tests::fit_cools_an_overconfident_model：对过度自信的 logits，拟合出的 T 大于 1，ECE 下降，T 在 [0.25, 8.0] 内。
  • 依赖： 无。不需要任何模型权重。
  • 单元： U6 到 U8。

P2 Qwen3 主干

  • 产出： crates/duan-qwen 的前向，包括 forward 和 forward_with，以及 KV 缓存。权重加载器 duan_qwen::load 已经实现，不作为练习。

  • 完成标准： 下面三个文件里所有 #[ignore = "P2"] 的测试都通过：

    • tests/components.rs：
      • RMSNorm 和手算结果一致；
      • RoPE 和按 rotate-half 约定手算的结果一致；
      • RoPE 在位置 0 是恒等变换，并且保持范数；
      • 旋转后的注意力分数只取决于相对位置。
    • tests/forward.rs，用微型配置和随机权重：
      • 改动后面的 token，不影响前面的输出；
      • 右填充不影响真实 token 的输出；
      • KV 缓存增量前向和整段前向一致；
      • 分段前向和逐段单独前向相差小于 1e-4；
      • 交换两个选项段只交换它们的输出。
    • tests/align.rs：FP32 下，嵌入层、逐层隐藏状态和最终隐藏状态都和 transformers 一致。判定标准是每个元素满足 |ours − ref| ≤ 1e-4 · (1 + |ref|)，相对误差那一项是给某些通道的大激活留余量。需要设置环境变量 DUAN_QWEN_DIR（权重目录）和 DUAN_REF_DIR（tools/ref/qwen_ref.py 的输出目录）。

    另外，能说清 Qwen3 每一处和标准 Llama 结构不同的细节。

  • 依赖： 无。

  • 单元： U9 到 U12。

P3 中文数据

  • 产出：
    • tools/data/sources_zh.json 中至少一个许可证核实过的中文数据源，convert_zh.py 中对应的转换器；
    • 防泄漏去重和 manifest；
    • 一份只来自测试集的中文评测集；
    • design.md 第 3.6 节的标记 id 和第 3.7 节的 state 预算。
  • 完成标准：
    • kime eval <suite> --data-manifest <manifest> 检查通过（至少要给一个 suite 文件，命令没有默认 suite）；
    • 每个被采用或排除的数据源，license_note 里都写了依据；
    • design.md 中两个「待定（P3）」都已经填上。
  • 依赖： 无。都在 CPU 上完成。
  • 单元： U13、U14。

P4 决策层与对照

  • 产出：
    • 新建 crate duan-decide：按 design.md 第 3 节渲染请求，生成位置和偏置，实现第 5 节的决策头和第 6 节的训练循环；
    • 第一个中文决策模型，以及 experiments/ 下的训练报告。
  • 完成标准：
    • duan-decide 的测试全部通过：
      • 交换两个选项只交换它们的 logit；
      • 选项分批前向和一次前向的 logits 一致；
      • 同一请求里多加一个问题，其他问题的 logits 不变；
      • 同一问题单独算和放在批里算，结果一致。
    • 报告满足终点的验收标准，并包含：
      • 两个零样本参考：laya-multilingual 原版和 Qwen3 零样本；
      • 「标记放在选项前面」布局的翻转率对照；
      • design.md 第 8 节中所有「待定（P4）」的结论。
  • 依赖： P1、P2、P3。
  • 硬件： 24 GB 级别的硬件，见硬件分级。只有 CPU 的机器只能在微型配置上调通流程。
  • 单元： U15 到 U17。

补全

P6 分桶校准与置信度头

  • 产出： 按（题型、k 桶、语言组）分桶的温度，写进 kime 格式的 calibration.json；一个冻结主干训练的置信度头。
  • 完成标准：
    • 分桶前后的 ECE 写进 calibration.json；
    • 置信度头的 AUROC 比 max(p) 至少高 0.01，否则按 kime 的规格不发布它，act_probability 退回 max(p)。
  • 依赖： P4。
  • 注意： kime 0.1.8 会静默忽略 kime.policy 字段，所以决策代价矩阵的阈值要自己实现，不能调用 kime 来验证。见 P0 实测记录。

P8 state 缓存与推理延迟

  • 产出： 带 state 缓存的推理实现，以及一份延迟报告。
  • 完成标准：
    • 同一个 state 上问 10 个问题的耗时，远小于问 1 个问题的 10 倍。作为对照，Laya 实测是 7.3 倍；
    • 短 state 的单次决策，在 GPU 上达到个位数毫秒；
    • int8 量化后，argmax 翻转率低于事先定好的阈值。
  • 依赖： P4。

硬件分级

按能力分级，不绑定具体机器。同一份代码在所有级别上都要能跑：Burn 后端由 feature 和运行时的 Device 决定，Python 环境见 tools/ref/README.md。

级别例子Burn 后端用于说明
只有 CPU任意笔记本，Intel MacflexP0、P1、P3，以及 P2 的 FP32 对齐对齐慢，但可行。Intel Mac 上 torch 最高只到 2.2.2；它的 AMD 显卡没有验证过，按只有 CPU 规划
24 GB 统一内存的 Apple SiliconM3 24 GBmetalP2 到 P9统一内存和系统共用，全量微调要用小批量或梯度检查点
24 GB 显存的 NVIDIA 显卡RTX 4090，L4cudaP2 到 P9训练最快。P5 的 CUDA 优化需要这一级
大模型 API 预算P7先用几千条数据估算成本，再决定规模

0.6B 全量微调时，FP32 的权重、梯度和 AdamW 状态合计约 10 GB，再加上激活。只训顶部几层时宽裕得多。

不同设备、不同后端得到的数字不能直接混在一起比较：实验记录必须写明设备、后端和精度，速度对比只在同一台机器上做。正确性以 CPU 上的 FP32 为准，其他后端先和它对齐，再用来训练。

风险

  • Qwen3 在中文上更强，目前只是假设。 P4 的同数据对照就是用来检验它的。如果输了，照实报告差距，并按 design.md 第 4.1 节重新评估这个选择：那里的结构收益仍然成立，但能力收益要重新算。
  • 选项之间不能直接比较。 这是分段布局的代价，见 design.md 第 3.4 节。只有出现确实需要比较的问题类型时，才加联合打分。
  • 延迟有上限。 0.6B 在 GPU 上能做到个位数毫秒，做不到亚毫秒，在 CPU 上则是几百毫秒。需要更低延迟时，走蒸馏。
  • 后端之间有差异。 不同后端的数值不会逐位相同，算子覆盖也不一样。某个后端缺算子，或结果超出误差时，记进实验目录，换后端继续；不要为了单个后端改模型代码。
  • 许可证与服务条款。 Qwen3-0.6B 是 Apache-2.0。每个数据集都要确认允许训练，合成数据要确认大模型的服务条款允许用输出训练分类器。拿不准的一律排除。

和 kime 的关系

  • 版本差异： DUAN 使用 Burn 0.22.1，kime 固定在 0.21。向 kime 贡献代码时，需要移植回 0.21。
  • 维护情况： kime 只有一位维护者。提交 PR 之前，先在相关 issue 下确认作者是否还在维护。
  • 可以回馈的方向： 校准（kime #45）、中文数据源，以及 Burn 上的训练性能（kime #181）。这些都和 DUAN 的数据格式、评测保持兼容，随时可以回馈。
